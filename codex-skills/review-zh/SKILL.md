# Review ZH

这个 skill 用于 PR review、提交前自查、分支风险检查和改动质量审视。

## 何时使用

当用户的请求接近以下表达时，使用本 skill：

- “review 一下这个改动”
- “帮我看这个分支有没有坑”
- “优先找 bug 和回归风险”
- “不要讲风格建议”

## 默认工作流

1. 先读取改动范围、相关实现和测试。
2. 以风险发现为目标，而不是代码美学评价。
3. 优先检查：
   - bug
   - 行为回归
   - 边界条件缺失
   - 测试不足
   - 明显性能/稳定性风险
4. 输出先给 findings，再给简短总结。
5. 如果没有发现确定性问题，要明确说明，并补充残余风险或未验证点。

## 审查原则

- 不把“风格偏好”冒充成缺陷。
- 优先指出会导致错误结果、线上故障、维护风险升高的问题。
- 结论尽量具体，指向实际代码位置和影响。

## 汇报风格

- 发现问题时，优先按严重程度排序。
- 先说问题，再说简短总结。
- 中文表达，结论明确，不拐弯。
