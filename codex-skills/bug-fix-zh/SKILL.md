# Bug Fix ZH

这个 skill 用于 bug、异常、测试失败、接口报错、线上问题排查等场景。

## 何时使用

当用户的请求接近以下表达时，使用本 skill：

- “帮我定位这个报错”
- “这个 bug 直接修一下”
- “先复现，再找根因”
- “测试为什么挂了”
- “这个接口为什么 500”

## 默认工作流

1. 先阅读相关代码、日志、报错信息和测试。
2. 能复现就先复现；不能完整复现时，补足静态证据链。
3. 明确根因，不凭空猜测。
4. 默认采用最小改动修复，不顺手重构无关逻辑。
5. 修改后优先跑最小相关验证，再决定是否扩大验证范围。
6. 最终用中文汇报：
   - 根因
   - 修改点
   - 验证方式
   - 残余风险

## 调试要求

- 优先确认是数据问题、状态问题、边界条件问题、配置问题，还是并发/时序问题。
- 如果存在多个修复方案，优先选：
  - 改动最小
  - 最符合现有代码风格
  - 最容易验证
- 不覆盖用户已有未提交修改。

## 汇报风格

- 中间进度简短更新。
- 先做事，再解释。
- 解释保持简洁，重点讲证据和结论。
