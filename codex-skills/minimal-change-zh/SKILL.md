# Minimal Change ZH

这个 skill 用于小功能开发、增量改动、兼容性修改和保守型迭代。

## 何时使用

当用户的请求接近以下表达时，使用本 skill：

- “最小改动做这个需求”
- “不要重构”
- “保持现有接口不变”
- “在现有逻辑上加一个功能”
- “只改相关代码，不要扩散”

## 默认工作流

1. 先理解相关实现、调用链和现有约束。
2. 尽量复用现有逻辑，不平地起新层次。
3. 保持现有接口、结构和行为稳定，除非用户明确要求改变。
4. 只修改和需求直接相关的代码。
5. 修改后做最小相关验证，并说明是否存在未覆盖场景。

## 改动原则

- 优先兼容现有代码风格和设计。
- 不顺手清理无关代码。
- 不引入额外框架或新模式，除非当前实现已经在使用。
- 如果发现更大的结构问题，先完成当前需求，再作为后续建议提出。

## 汇报风格

- 说明为什么选择这个最小改动点。
- 说明是否保持了原有行为和接口。
- 简述验证结果和残余风险。
